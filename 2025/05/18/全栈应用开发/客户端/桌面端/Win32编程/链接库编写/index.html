静态链接库(.lib)

静态链接库是编译后生成的 .lib 文件（Windows），包含目标代码（函数实现），使用时，链接器把 .lib 里的代码直接嵌入到可执行文件中

  • 优点：调用像普通函数，运行时不依赖 DLL
  • 缺点：生成的 EXE 较大，更新库需要重新编译

编译后，会生成：

  • MyMath.lib → 静态库
  • MyMath.obj → 中间目标文件
  • （可选）MyMath.pdb → 调试信息

使用静态库:

静态链接库的使用有两种方法：

第一种方法：将生成的.h与.lib文件复制到项目根目录，然后在代码中引用：

第二种方法：将xxxx.h与xxxx.lib文件复制到VC6安装目录，与库文件放在一起，然后在工程->设置->连接->对象/库模块中添加xxxx.lib，最后就可以像使用C语言库一样使用它了

  • 头文件路径：C:\Program Files\Microsoft Visual Studio\VC98\Include
  • 静态链接库路径：C:\Program Files\Microsoft Visual Studio\VC98\Lib

动态链接库

动态链接库弥补了静态链接库的两个缺点，动态链接库，是微软公司在微软Windows操作系统中对共享函数库概念的一种实现方式，这些库函数的文件扩展名称为：.dll、.ocx（包含ActiveX控制的库）。可在运行时加载到程序中，被多个程序共享

  • 优点：程序小、支持插件式架构、更新 DLL 无需重新编译 EXE
  • 缺点：调用时需要保证 DLL 可访问（路径或显式加载）、类导出复杂

主要特点：

  • 代码共享：多个进程可同时使用同一个DLL
  • 模块化开发：功能解耦，便于维护更新
  • 节省内存：物理内存中只保留一份副本
  • 延迟加载：运行时按需加载，减少启动时间

隐式链接

在编译阶段就告诉链接器需要用某个 DLL 对应的 **import library (.lib)**，运行时系统会自动加载 DLL。

流程：

  1. 编译时链接 .lib 文件 → EXE 中包含 DLL 的符号信息
  2. 程序启动时 → 系统自动寻找 DLL 并加载
  3. 调用 DLL 内函数像调用普通函数一样，无需 GetProcAddress

使用隐式链接，编译器会将链接的DLL文件存放到导入表中：

优点：

  • 调用方式简单，像普通函数调用
  • 不需要手动管理 LoadLibrary 和函数指针
  • 编译器和链接器自动处理依赖

缺点：

  • 程序启动时必须能找到 DLL（路径必须正确，否则启动失败）
  • DLL 更新时仍需保证版本兼容

配置步骤（VS 工程）

假设有 DLL：MyMath.dll，并且有 import library MyMath.lib 和头文件 MyMath.h：

  1. 包含头文件：Project → C/C++ → General → Additional Include Directories → DLL 的头文件路径
  2. 链接库：
    • Project → Linker → General → Additional Library Directories → .lib 文件所在目录
    • Project → Linker → Input → Additional Dependencies → MyMath.lib
  3. DLL 路径：运行时必须能找到 DLL，可以：
    • 放在 EXE 同目录
    • 系统 PATH 下
    • 使用 VS 的 Debugging → Environment 设置临时 PATH
  4. 调用：像普通函数调用一样，无需手动加载
