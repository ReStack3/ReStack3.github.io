这种“先拆后建”的保守操作，是编译器开发中保证 IR 正确性的常见模式。

深入解析 Switch 结构中的 Default Case

1. Default Case 的设计矛盾

理论上的“完美情况”
  • 理想假设：
    所有后继基本块都已通过 addCase 添加到 switch，每个块都有对应的 case 值，因此 default 分支理论上永远不会执行。
  • 矛盾点：
    如果 default 无用，为何不直接删除它？
实际代码中的必要性
  • LLVM 的限制：
    SwitchInst 必须包含一个 default 分支（即使逻辑上不需要），这是由 LLVM IR 的语法规则决定的。

2. 为什么需要判断“无后继 case 值”？

    ：

  3. 问题：
    如果 bb2 是终止块（如 ret），它不会被添加到 switch 的 case 中（因为无后继操作），此时 findCaseDest(bb2) 返回 NULL。

Default 的容错作用
  • 结果：
    虽然 default 分支永远不会被执行（因为所有有效块都有 case），但它作为“安全网”存在，避免因代码缺陷导致未定义行为。

3. 为什么说 Default 是“子分发器”？

控制流平坦化的本质
  • 原始控制流：
    基本块通过直接跳转连接（如 bb1 → bb2）。
  • 平坦化后：
    所有跳转被替换为对 switchVar 的赋值，由 switch 统一分发执行。
Default 的角色
  • 冗余但必要的分发节点：
    switch 的语法要求必须覆盖所有可能的 switchVar 值，即使某些值在逻辑上不可能出现。
  • 类比：
    类似编程中的 default: break;，即使 case 已覆盖所有枚举值，仍需保留 default 以满足语法要求。

5. 总结

关键点 解释
LLVM 语法要求 SwitchInst 必须包含 default 分支，即使逻辑上不需要。
容错机制 处理未预期的 switchVar 值（如未添加 case 的终止块）。
“子分发器”比喻 default 是控制流的最后保障，确保所有路径都有定义的行为。
实际影响 无运行时开销（因 default 永不执行），但维护了 IR 的合法性和鲁棒性。

最终结论

default 分支的存在是 LLVM 语法限制 和 工程健壮性 的共同结果。虽然理论上所有有效块都应被 switch 覆盖，但保留 default 可以：

  1. 避免因代码生成缺陷导致未定义行为。
  2. 满足 LLVM IR 对 SwitchInst 的强制性语法要求。
  3. 在极端情况下（如未处理的终止块）提供安全回退路径。

反混淆

模拟执行与符号执行

unicorn模拟执行：核心在于找到全部真实块，之后从首个真实块使用unicorn模拟执行混淆的程序，直到运行到下一个真实块，这里需要注意的是真实块中的分支指令需要单独处理。

angr符号执行解决控制流平坦化：通过符号执行来确定真实块之间的前后关系，真实块之间的前后关系又分为两类：

  1. 有一个确定的后继块
  2. 有两个后继块，跳转到哪个由某个条件决定

第一种情况非常好处理，我们从一个真实块A开始符号执行，直到碰到下一个真实块B，那么我们就确定了一对基本块的执行顺序A→B。

第二种情况我们需要先令该条件为True，然后进行符号执行，得到一个后继真实块的地址；再令条件为False，然后进行符号执行，得到另一个后继真实块的地址。思路比较简单，但代码写起来会稍微有点复杂。

Unicorn（模拟执行） 和 Angr（符号执行） 在解决 OLLVM 控制流平坦化时的核心思路 高度一致，均围绕 识别真实块 和 恢复真实控制流 展开

核心思路的一致性:

步骤 Unicorn 模拟执行 Angr 符号执行
目标 恢复被平坦化隐藏的真实控制流 同左
关键方法 动态执行找到真实块间的跳转关系 符号化分析推导真实块间的可达性
处理分支 强制设置分支条件，观察执行路径 分情况约束条件（True/False）求解路径
输出结果 真实块间的直接跳转边（A→B） 同左

共同逻辑：

  1. 识别真实块：过滤掉 Dispatcher 和虚假块，保留实际有意义的代码块。
  2. 恢复跳转关系：通过执行（动态或符号化）确定真实块之间的前后继关系。
  3. 重建 CFG：基于跳转关系生成简化后的控制流图。

技术实现的差异:

维度 Unicorn Angr
执行方式 动态执行（具体输入驱动） 符号执行（抽象输入覆盖所有路径）

适用场景 已知输入或需快速验证 复杂分支或需全路径分析
工具链 轻量级，适合嵌入自定义工具 重量级，适合复杂分析
