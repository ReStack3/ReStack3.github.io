引用计数

引用计数是一种内存管理技术，通过跟踪对象被引用的次数来决定何时释放其资源。

基本思想:

  • 每个对象附带一个计数器
  • 当新引用指向对象时，计数器递增
  • 当引用失效时，计数器递减
  • 当计数器归零时，自动释放对象

条件执行的优化

核心概念：CPU流水线

一个汽车装配流水线，它被分成多个阶段（安装发动机、安装车门、喷漆等）。当第一辆车在喷漆时，第二辆车已经在安装车门，第三辆车在安装发动机。这样同时处理多辆车，大大提高了效率。

CPU流水线也是类似的原理：

取指 -> 译码 -> 执行 -> 访存 -> 写回.当第N条指令在执行时，第N+1条指令在译码，第N+2条指令在取指。理想情况下，每个时钟周期都能完成一条指令。

编译器优化

虚函数

虚函数可能造成性能损失

  • 构造函数必须初始化Vptr
  • 虚函数是通过指针间接调用的，所以必须先得到指向虚函数表的指针，然后再获得正确的函数偏移量
  • 内联是编译时决定的，编译器不可能把运行时才解析的虚函数设置为内联

无法内联函数造成的损失

必须允许编译器在编译期间就解析函数的绑定。通过对类选择硬编码或者将它作为模板参数来传递，可以避免使用动态绑定。(模板把解析的步骤从运行期间提到编译期间)

模板与继承

这是一种基于编译期决议的替代方案，主要通过CRTP模式实现。

工作原理

  • 使用模板基类，派生类作为模板参数传入。
  • 通过静态转换将this指针转换为派生类指针。
  • 所有函数调用在编译时就确定，没有运行时查找。
  1. 零运行时开销：没有vptr/vtable查找。函数调用在编译时直接绑定。
  2. 可内联性：编译器能看到具体的函数实现，可以轻松内联。对于小型函数，这能带来巨大性能提升。
  3. 缓存友好：处理同质集合（如vector<Circle>），数据在内存中连续分布。更好的数据局部性，更高的缓存命中率。
特性 继承（动态多态） 模板（静态多态）
决议时间 运行时 编译时
性能开销 有（虚函数调用） 无（直接调用）
内联可能 几乎不可能 很可能
内存布局 异构，不连续 同质，连续
二进制大小 较小 较大（模板实例化）
灵活性 高（运行时切换） 低（编译时确定）
调试难度 相对容易 相对困难

临时对象的生命周期

基本规则：临时对象的生命周期持续到包含它的那个完整表达式结束时为止。

  • 完整表达式：通常不是一个子表达式。例如，在 int x = f1() + f2() * f3(); 中，整个初始化语句是一个完整表达式。当分号 ; 出现时，所有在这个语句中创建的临时对象（除了被绑定到引用上的，见下文）都会被销毁。

重要的特例：绑定到常量引用/右值引用

当将一个临时对象绑定到一个常量左值引用 或 右值引用 上时，它的生命周期会被延长，变得与这个引用的生命周期相同。

为什么不能绑定到非const左值引用？
因为从逻辑上讲，如果能修改一个临时对象（通过非const引用），但这个对象马上就会被销毁，那么你的修改就毫无意义，这很容易导致程序员犯错。所以C++语言标准禁止这样做。

临时对象的产生和销毁（调用构造函数和析构函数）是有成本的。在性能敏感的代码中（如循环、数值计算），大量的临时对象会严重影响效率。

现代C++的解决方案：移动语义

C++11引入的移动语义 极大地优化了临时对象的使用。因为临时对象是“将亡值”，它的资源可以被“转移”而不是“拷贝”。

别让异常逃离析构函数

在析构函数中，如果有可能抛出异常，必须要在析构函数内部捕获并处理它，绝不能让它传播到析构函数外部。

方案 做法 适用场景 优点 缺点
吞掉异常 try-catch在析构函数内部 非关键操作 简单，保证程序继续 可能隐藏重要错误
显式释放方法 提供close()等方法 需要错误处理的资源 用户可处理异常，更灵活 依赖用户正确调用
终止程序 调用std::abort() 关键资源失败意味着程序状态不可信 明确失败，避免数据损坏 用户体验差
自定义删除器 与智能指针结合 现代C++资源管理 类型安全，自动管理 稍复杂

核心原则：

  1. 析构函数绝不能让异常传播到外部
  2. 在栈展开期间（处理异常时），析构函数抛异常会导致std::terminate()
  3. 优先提供显式释放方法，让用户有机会处理异常
  4. 析构函数中必须捕获所有可能的异常
  5. 使用noexcept标记析构函数，明确承诺不抛异常

记住：析构函数应该专注于资源释放，而不是错误处理。把错误处理的机会留给调用者。

当自定义拷贝操作时，问自己：

场景 错误做法 正确做法
新增成员变量 忘记在新成员复制 更新所有拷贝操作，复制新成员
继承体系 只复制派生类成员 调用基类拷贝操作Base(other)或Base::operator=(other)
动态资源 浅拷贝指针 深拷贝或使用智能指针

检查清单：

  1. 是否复制了所有非静态数据成员？
  2. 在继承体系中，是否正确处理了基类部分？
  3. 是否检查了自赋值情况？（拷贝赋值中）
  4. 异常安全是否得到保证？
  5. 是否真的需要自定义拷贝操作？能否用= default？

要么完全不自定义拷贝操作（让编译器生成），要么确保完全正确地复制所有成分。 任何部分拷贝都会导致对象状态不一致，这是很难调试的bug来源。记住：编译器生成的拷贝操作总是正确的，因为它知道类的完整结构。当你接管这个责任时，你必须同样正确。

继承和面对对象设计

区分接口继承和实现继承

  • 接口继承：定义”做什么“（What）的契约，关注行为规范，不关心具体实现，在C++中通过纯虚函数实现
  • 实现继承：提供”怎么做“（How）的具体代码，关注代码复用和具体实现，在C++中通过非虚函数和普通虚函数实现

is-a 和 has-a

is-a 关系（继承）表示”是一个“的关系，用于分类和特化，在C++中通过公有继承实现，is-a 关系描述的是类型之间的层次关系，派生类是基类的一种特殊形式。

has-a 关系（组合）表示”有一个“的关系，用于包含和组合，在C++中通过成员变量实现，has-a 关系描述的是整体与部分的关系，一个对象包含另一个对象作为其组成部分。
