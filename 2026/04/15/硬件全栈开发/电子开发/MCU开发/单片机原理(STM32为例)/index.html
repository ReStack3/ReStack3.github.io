单片机原理(STM32为例)

简单介绍

单片机是一种将中央处理器（CPU）、存储器（RAM/ROM）、输入输出接口（I/O）、定时器/计数器等主要计算机部件集成在一小块芯片上，形成的微型计算机系统。也常提其英文缩写 MCU（Microcontroller Unit）。

它体积小、成本低、功耗低、控制功能强、可靠性高。与通用计算机（如PC）的区别在于：单片机通常用于专用控制，而非通用计算。原理跟计算机一样。只是由于高度集成化，它的运算速度， 电压等级，存储容量会小很多。运行的程序会精简很多。以至于一些都没有操作系统。

其被广泛用于智能家电、汽车电子、工业控制和物联网设备中。开发人员常用C语言和Arduino或Keil等工具为单片机编写程序，实现对外部设备的检测与控制。常见的单片机包括8051、AVR、PIC和STM32系列。

硬件基础

GPIO与中断

通用功能输入输出

GPIO 是 General Purpose Input/Output 的缩写，中文意思是 通用输入/输出。简单来说，它就是单片机（Microcontroller Unit, MCU）上那些可以用来与外部世界进行数字信号交互的物理引脚（Pin）。可以把单片机的GPIO引脚想象成可以编程控制的、非常小的电子开关或信号端口。

类别 模式 中文名 典型用途
输入模式 浮空输入 不接上拉/下拉电阻，电平由外部决定 读取不确定电平的信号（如UART RX，但易受干扰）
上拉输入 内部接入上拉电阻，默认高电平 读取按键（按下接地，未按下读高）
下拉输入 内部接入下拉电阻，默认低电平 读取部分传感器（输出低有效或高阻态）
模拟输入 不经过TTL施密特触发器，直接给ADC ADC采集模拟电压
输出模式 开漏输出 输出高时为高阻态，需外接上拉电阻 I2C总线（多设备可共用一条线）、驱动不同电压设备
推挽输出 高低电平都能直接驱动（最常用） 驱动LED、蜂鸣器、普通数字信号
复用推挽 引脚功能由内部外设（如USART、SPI）控制 UART、SPI、PWM输出、控制专用芯片
复用开漏 引脚功能由外设控制，且为开漏 I2C的SCL/SDA引脚、某些特殊总线
复用双向 外设自动切换方向 1-Wire、SWD调试接口等

所有端口都有外部中断能力,为了使用外部中断线,端口必须配置成输入模式。

  • 电平逻辑：
    • TTL电平：常见于5V系统，高电平 > 2.0V，低电平 < 0.8V。
    • CMOS电平：常见于3.3V系统，高电平 > 0.7 * VCC，低电平 < 0.3 * VCC。
  • 驱动能力：一个GPIO引脚能安全输出的最大电流（通常几毫安到几十毫安）。直接驱动大功率负载（如大电机）会烧毁引脚，需要使用晶体管、MOSFET或继电器驱动。
  • 悬空：输入模式下，如果引脚既没接高电平也没接低电平，其电平状态会不稳定，受电磁干扰而乱跳。解决方法：启用内部上拉/下拉电阻，或外接电阻。
模式 方向 作用 例子
输出 单片机 -> 外部 控制外部设备 点灯、驱动蜂鸣器、控制继电器
输入 外部 -> 单片机 读取外部状态 读按键、读简单传感器
复用 双向/专用 使用内置硬件外设 串口通信、PWM调光、ADC采样

外部中断 (EXTI)

外部中断（EXTI）是一种硬件机制，它允许单片机在检测到指定GPIO引脚上的电平变化（如上升沿、下降沿）时，立即暂停当前正在执行的代码，去执行一个预先定义好的特殊函数（中断服务函数），执行完后再回去继续执行原来的代码。

通用定时器

定时器/计数器本质上就是一个“可以自动数数的硬件计数器”。它数的是由内部时钟源提供的脉冲（时间），或者是由外部引脚输入的变化信号（事件）。【通过寄存器选择 TMR0 的计数信号源：来自内部时钟（晶振分频）时是定时器模式，来自外部引脚脉冲时是计数器模式。】

直接存储器读取DMA

DMA 是一个专门负责在内存和外设之间、或内存与内存之间搬运数据的“硬件小助手”。它可以在不需要CPU参与的情况下，独立完成大量数据的快速转移。

配置要素

  • 源地址：数据从哪里来。例如：&ADC1->DR（ADC数据寄存器的地址）。
  • 目标地址：数据要搬到哪里去。例如：&myBuffer[0]（你自己定义的数组的首地址）。
  • 传输数量：总共要搬多少个数据。例如：1000。
  • 传输方向：
    • 外设 → 内存（最常见，如ADC采集、接收UART数据）
    • 内存 → 外设（如发送UART数据、DAC输出波形）
    • 内存 → 内存（仅部分DMA支持，如M2M模式）
  • 触发源：什么时候开始搬一次数据。例如：
    • ADC转换完成信号
    • 定时器更新信号
    • UART接收寄存器非空信号
    • 软件触发
  • 循环模式：
    • 普通模式：搬完指定数量的数据后就停止。
    • 循环模式：搬完最后一个数据后，自动重新从头开始，无限循环（非常适合ADC连续采样、PWM控制）。

工作流程

阶段1：触发与仲裁（对应通用流程的“DMA请求”）

  1. 事件触发：外设（如ADC、USART、定时器）发生一个事件，向外发送一个DMA请求信号。
  2. 请求映射：不同外设的请求通过“逻辑或”进入DMA控制器。关键：某时刻一个通道只能处理一个请求，所以需要在配置时选择正确的映射（如表8-xx）。
  3. 仲裁（优先级判断）：DMA控制器收到多个通道的请求后，根据以下规则决定先响应哪个：
    • 软件优先级（4级）：最高 > 高 > 中等 > 低（可编程）。
    • 硬件优先级（同软件级时）：通道编号越低，优先级越高（如通道2 > 通道4）。

阶段2：握手与总线控制（对应通用流程的“DMA响应”）

  • DMA控制器选择了高优先级的请求后，向外设发送一个应答信号（握手）。
  • 外设收到应答信号后，立即撤销请求。
  • DMA控制器检测到请求撤销后，也撤销应答信号。一次握手完成。
  • 注意：这里隐含了DMA控制器会通过总线裁决逻辑向CPU请求总线控制权的过程（与上一轮对话一致）。获得总线后，才进入下一阶段。

阶段3：传输控制（对应通用流程的“DMA传输”）

这是STM32 DMA的特色，你的资料详细描述了传输过程中的关键控制：

  • 数据宽度与地址自增：
    • 数据宽度可设（1、2、4字节）。
    • 外设和存储器的地址指针可独立选择是否自增（增量值 = 数据宽度）。
    • 常见场景：从ADC数据寄存器（固定地址）读取到数组（自增地址）。
  • 传输数量：可设置最大65535次传输。
  • 传输模式：
    • 非循环模式：传输完成（计数器归零）后停止DMA操作。
    • 循环模式：传输完成（计数器归零）后自动恢复初始值，并继续DMA操作。常用于ADC扫描模式、音频环形缓冲区。
  • 存储器到存储器模式：
    • 无需外设请求，直接触发DMA传输。
    • 注意：该模式不能与循环模式同时使用。通常用于大块内存复制。

阶段4：中断与结束（对应通用流程的“DMA结束”）

  • 中断类型（可独立使能）：
    • 半传输中断（HTIF）：当传输完成一半时置位，可产生中断。常用于双缓冲处理（在处理前半部分的同时，DMA继续填充后半部分）。
    • 传输完成中断（TCIF）：当传输计数器归零时置位，可产生中断。通知CPU数据已全部搬运完毕。
    • 传输错误中断（FEIF）：当DMA读写过程中发生总线错误时置位，可产生中断。此时硬件会自动清除该通道的配置寄存器位，并停止该通道操作。
  • 结束后的动作：
    • 非循环模式：通道停止，等待重新配置启动。
    • 循环模式：自动重置计数器，继续传输，直到被软件关闭。

模/数转换器

ADC 是一个将连续的模拟电压信号（如 0V ~ 3.3V）转换为离散的数字值（如 0 ~ 4095）的硬件模块。

输入/输出通道是计算机与工业生产过程交换信息的桥梁。按照信号输入/输出的方式可 分为输入通道和输出通道。

单片机应用系统中的输入通道用于采集控制或测量对象的各类变量，其中数字信号可直接通过GPIO口输入，若信号幅值过小则需先经放大器放大以满足TTL或CMOS电平要求；

而连续变化的模拟信号必须先经模/数转换器（ADC）转换为数字量后才能被单片机处理，若原始物理量（如温度、压力、流量、速度等）是非电信号，则还需先通过传感器转换为模拟电信号，必要时再经放大器放大。

输出通道则承担数/模转换、功率放大驱动和干扰信号防治三项主要作用：首先，单片机输出的数字控制信号需要通过D/A转换器（DAC）转换为模拟电压或电流；其次，由于转换后的模拟信号通常功率不足，需要经过功率放大才能驱动外部负载；最后，后向输出通道靠近控制对象，工作环境恶劣，驱动系统极易通过信号通道、电源、空间电磁场甚至机械方式对单片机系统造成干扰，因此必须采取信号隔离、电源隔离以及大功率开关过零切换等措施进行防治。最终，单片机系统的处理结果可以以开关量、数字量或频率量的形式输出。

模式控制

  • 规则组：按部就班的日常工作。你事先排好一个任务列表（比如先测温度、再测湿度、再测压力），ADC就按这个顺序一遍遍地循环执行。
  • 注入组：突发的紧急任务。不管当前规则组执行到哪一步，都要立刻打断，优先执行注入组的测量，测完再回去继续刚才被打断的规则任务。

在STM32 ADC中的实际差异

对比项 规则组 注入组
优先级 低（可被打断） 高（打断别人）
最多通道数 16个 4个
数据寄存器 只有1个（ADC_DR） 不配合DMA会被覆盖 4个独立的（ADC_JDR1~4） 每个通道结果自动保存
典型用途 常规传感器轮询 过流保护、紧急位置检测

打断行为 被注入打断时， 当前正在转换的规则通道作废 注入转换期间， 规则事件来了也不理（不会被中断）

ADC的运行模式从两个维度讲清楚：转换模式和组类型。

这两个概念容易混淆，先一句话区分：

  • 转换模式：决定ADC“什么时候开始、什么时候结束”（比如单次、连续、扫描、间断）
  • 组类型：决定ADC“采集哪些通道、优先级如何”（规则组、注入组）

中断和DMA请求

这两个是ADC数据搬运和事件通知的核心机制

  1. ADC 中断 规则组和注入组转换结束时能产生中断,当模拟看门狗状态位被设置为1时,也能产生 中断。它们都有独立的中断使能位。
  2. DMA 请求 因为规则通道转换的值存储在一个仅有的数据寄存器中,所以当转换多个规则通道时需 要使用 DMA,这可以避免丢失已经存储在 ADC_DR 寄存器中的数据。只有在规则通道转换 结束时才产生 DMA 请求,并将转换的数据从 ADC_DR 寄存器传输到用户指定的目的地址。
