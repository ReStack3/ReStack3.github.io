单片机原理(STM32为例)

简单介绍

单片机是一种将中央处理器（CPU）、存储器（RAM/ROM）、输入输出接口（I/O）、定时器/计数器等主要计算机部件集成在一小块芯片上，形成的微型计算机系统。也常提其英文缩写 MCU（Microcontroller Unit）。

它体积小、成本低、功耗低、控制功能强、可靠性高。与通用计算机（如PC）的区别在于：单片机通常用于专用控制，而非通用计算。原理跟计算机一样。只是由于高度集成化，它的运算速度， 电压等级，存储容量会小很多。运行的程序会精简很多。以至于一些都没有操作系统。

其被广泛用于智能家电、汽车电子、工业控制和物联网设备中。开发人员常用C语言和Arduino或Keil等工具为单片机编写程序，实现对外部设备的检测与控制。常见的单片机包括8051、AVR、PIC和STM32系列。

下面通过结合Stm32单片机来讲述单片机的基本原理

GPIO与中断

通用输入输出

GPIO 是 General Purpose Input/Output 的缩写，中文意思是 通用输入/输出。简单来说，它就是单片机(Microcontroller Unit, MCU)上那些可以用来与外部世界进行数字信号交互的物理引脚（Pin）。可以把单片机的GPIO引脚想象成可以编程控制的、非常小的电子开关或信号端口。

  • 推挽输出：主动输出高电平和低电平。输出高电平时，引脚被强力拉到VCC（如3.3V）；输出低电平时，被强力拉到GND（0V）。驱动能力强，适合驱动LED、蜂鸣器等。
  • 开漏输出：只能主动输出低电平。输出高电平时，引脚处于高阻态（相当于断开、悬空）。要想输出高电平，必须在外部加一个上拉电阻。适合电平匹配、总线共享。
  • 浮空输入：按键不按时本应是高电平，但由于引脚“悬空”（既不强拉高也不强拉低），引脚上的电压会因电磁干扰、静电等外部噪声而随机波动，导致读取值忽高忽低。

所有端口都有外部中断能力,为了使用外部中断线,端口必须配置成输入模式。

  • 电平逻辑：
    • TTL电平：常见于5V系统，高电平 > 2.0V，低电平 < 0.8V。
    • CMOS电平：常见于3.3V系统，高电平 > 0.7 * VCC，低电平 < 0.3 * VCC。
  • 驱动能力：一个GPIO引脚能安全输出的最大电流（通常几毫安到几十毫安）。直接驱动大功率负载（如大电机）会烧毁引脚，需要使用晶体管、MOSFET或继电器驱动。
  • 悬空：输入模式下，如果引脚既没接高电平也没接低电平，其电平状态会不稳定，受电磁干扰而乱跳。解决方法：启用内部上拉/下拉电阻，或外接电阻。
模式 方向 作用 例子
输出 单片机 -> 外部 控制外部设备 点灯、驱动蜂鸣器、控制继电器
输入 外部 -> 单片机 读取外部状态 读按键、读简单传感器
复用 双向/专用 使用内置硬件外设 串口通信、PWM调光、ADC采样

注意在STM32中，为了降低功耗，所有GPIO外设的时钟在默认情况下是关闭的。如果忘记使能时钟，你对GPIO配置寄存器的所有写入操作都将无效，引脚会处于默认状态（通常是模拟模式或浮空输入，电平不确定，常见为低电平或高阻态）。

中断系统

中断是 CPU 在执行程序过程中，遇到外部或内部紧急事件时，暂停当前任务，转而处理该事件，处理完毕后再返回继续执行原任务的一种机制。

内部中断

中断是 CPU 在执行程序过程中，遇到外部或内部紧急事件时，暂停当前任务，转而处理该事件，处理完毕后再返回继续执行原任务的一种机制。

STM32 中断向量表

STM32 有大量中断源，按优先级高低排列：

优先级 中断类型 示例
最高 系统异常 NMI、HardFault、MemManage
高 内核外设中断 SysTick、PendSV
中 外部中断（EXTI） GPIO 中断、RTC 闹钟
低 外设中断 定时器、USART、DMA、ADC

中断优先级管理（NVIC）

STM32 使用 NVIC（Nested Vectored Interrupt Controller） 管理中断：

  • 抢占优先级：高抢占优先级的中断可以打断低抢占优先级的中断
  • 响应优先级：同抢占优先级时，高响应优先级先执行，但不能互相打断
  • 优先级分组：决定抢占优先级和响应优先级各占多少位

外部中断 (EXTI)

外部中断（EXTI）是一种硬件机制，它允许单片机在检测到指定GPIO引脚上的电平变化（如上升沿、下降沿）时，立即暂停当前正在执行的代码，去执行一个预先定义好的特殊函数（中断服务函数），执行完后再回去继续执行原来的代码。

核心特点：

  • 支持最多 16 个 GPIO 中断线（EXTI0 ~ EXTI15）
  • 每个中断线对应一组引脚（PA0/PB0/PC0…共用 EXTI0）
  • 支持独立的边沿检测、中断屏蔽和挂起状态
  • 可配置为中断（通知 CPU）或事件（直接触发其他外设）

EXTI 的 16 条独立中断线：

中断线 可选的 GPIO 引脚 典型应用
EXTI0 PA0, PB0, PC0, PD0… 独立按键
EXTI1 PA1, PB1, PC1, PD1… 独立按键
EXTI2 PA2, PB2, PC2, PD2… 传感器中断
EXTI3 PA3, PB3, PC3, PD3… 传感器中断
EXTI4 PA4, PB4, PC4, PD4… 编码器信号
EXTI5 ~ EXTI9 PA5PA9, PB5PB9… 多个外设
EXTI10 ~ EXTI15 PA10PA15, PB10PB15… 矩阵键盘

重要限制：同一编号的 EXTI 线只能连接一个引脚。例如，PA0 和 PB0 不能同时作为独立中断源使用。

时钟系统

内部时钟

STM32包含了5个时钟源，分别为HSI、HSE、LSI、LSE、PLL。

  • HSI是高速内部时钟、RC振荡器，频率为8MHz；
  • HSE是高速外部时钟，即晶振，可接石英/陶瓷谐振器或接外部时钟源，频率范围为4MHz~16MHz；
  • LSI为低速内部时钟、RC振荡器，频率40kHz；
  • LSE为低速外部时钟，接32.768kHz晶振，作为RTC时钟源；
  • PLL为锁相环倍频输出，其时钟输入源可选择为HSI/2、HSE或者HSE/2。倍频可选择为2~16倍，但是其输出频率最大不得超过72MHz；

其中HSE/HSI 经过 PLL（锁相环）倍频后产生 SYSCLK（系统时钟）而SYSCLK 经过分频器产生总线时钟：AHB (HCLK) → **APB1/APB2 (PCLK1/PCLK2)**，即：时钟源 → 时钟树

外部时钟

STM32 定时器提供了两种外部时钟模式：

模式 时钟来源 配置方式 最大频率 典型应用
外部时钟模式1 TI1 或 TI2（通道1/2引脚） SMS=0b111 约 TIM_CLK/2 低频脉冲计数
外部时钟模式2 ETR 引脚（专用外部触发引脚） ECE=1 约 TIM_CLK/4 高频脉冲计数、频率测量

外部时钟是 STM32 定时器的一种工作模式，其核心特征是：定时器计数器的计数脉冲不是来自芯片内部的 APB 总线时钟（PCLK），而是来自外部引脚输入的信号。 这意味着每来一个外部脉冲，计数器就自动加1（或减1），完全独立于系统时钟运行。

STM32 提供了两种外部时钟模式：

  • 外部时钟模式1使用通用定时器的通道1或通道2引脚（TI1/TI2）作为时钟源，每个有效边沿驱动计数器计数，最大输入频率可达定时器时钟频率的一半；
  • 外部时钟模式2使用专用的 ETR（External Trigger）引脚作为时钟源，支持可编程的边沿检测、数字滤波和分频器（可对输入信号进行1、2、4、8分频后再计数），最大输入频率约为定时器时钟频率的四分之一。

以 TIM2 配置为外部时钟模式1为例，需要完成以下步骤：

使能 TIM2 和 GPIO 时钟，将对应引脚配置为复用功能模式，设置定时器的预分频器（PSC）和自动重装载值（ARR），然后将 TIM2_SMCR 寄存器的 SMS 位设为 0b111（选择外部时钟模式1），同时设置 TS 位选择 TI1 或 TI2 作为触发源，再配置 CCMR1 寄存器的 CC1S 位将通道设为输入模式，最后通过 CCER 寄存器的 CC1P 位选择上升沿或下降沿触发，使能定时器后计数器便开始跟随外部脉冲计数。

外部时钟模式下，计数器每计满 ARR+1 个脉冲就会产生更新事件（溢出中断），因此非常适合实现精确的脉冲计数：例如设置 ARR=99，每100个外部脉冲触发一次中断；或者连续读取 CNT 寄存器的值，直接获得两个时间点之间的脉冲个数。这种硬件计数方式完全由外设独立完成，不占用 CPU 资源，也不会因为软件响应延迟而漏掉脉冲。

实际应用中需要特别注意几点：首先，外部信号的脉宽必须至少大于2个定时器时钟周期，否则可能被漏计；其次，输入信号建议加数字滤波（通过 ETF 或 ICF 位配置）以消除毛刺干扰；再次，如果使用外部时钟模式1，会占用该通道的输入捕获功能，两者不能同时使用；最后，GPIO 的复用功能映射必须与定时器通道对应正确，具体引脚需查阅芯片数据手册。

STM32 内部集成了多个定时/计数器,根据型号不同,STM32 系列芯片最多包含8个定时/计数器。最终工作时钟 TIMx_CLK 取决于它挂在哪个总线上，即：时钟树 → 定时器：

  • 否则：TIM2~7 的时钟 = PCLK1 × 2

功能寄存器

通用定时器的时基单元由三个关键寄存器构成，定义了计数的时空尺度与边界：

  • 预分频器 (PSC)：将输入的时钟频率降速。16位，计数范围 1~65536。例如，TIMx_CLK为72MHz，设PSC=71，则分频后脉冲频率为 72MHz / (71+1) = 1MHz。记住，实际分频系数是 PSC + 1。
  • 计数器 (CNT)：硬件自动累加或递减的核心。16位，实时反映“数到哪儿了”。
  • 自动重装载寄存器 (ARR)：计数的目标值或上限。16位。当CNT达到ARR设定的值时，计数器会溢出（或下溢），产生更新事件（UEV），同时依据计数方向自动归零或重载到初始值。

这三位一体的配合，决定了 “数多快、数到几、数到头后怎么办”。

硬件状态机

外部触发及输入/输出通道，是通用定时器最强大的部分，让它远超一个简单计数器。一个通用定时器的外部交互通道大致可以分为三部分：

  1. 时钟/触发输入：从外部引脚接收信号，控制定时器的启停或作为计数时钟。当通道引脚出现预设的边沿（上升沿/下降沿/双沿）时，硬件会将当前计数器的值立即锁存到对应的捕获/比较寄存器（CCR）中，并触发中断或DMA。
  2. 捕获输入：从外部引脚接收信号，记录信号变化时刻的计数器值。锁定外部的“时间戳”。当外部引脚上的选定边沿到来时，硬件瞬间将当前CNT值拷贝到**捕获/比较寄存器 (CCR)**中。可用于精确测量外部信号的频率或脉宽。
  3. 比较输出：从定时器向外输出波形，当计数器值与比较寄存器匹配时改变引脚电平。在预设时刻产生外部动作。当CNT值与CCR相等时，硬件自动在对应引脚上执行指定动作（置高、拉低、翻转等）。这是产生PWM的物理基础。
  4. PWM生成：是输出比较的一种特殊应用。通过设定ARR决定周期（频率），设定CCR决定占空比。边沿对齐PWM常用向上计数，中央对齐PWM则用中央对齐模式。

直接存储器读取(DMA)

连续接收多个字节时数据丢失

CPU来不及处理数据导致的。UART的接收寄存器（DR）在收到下一个字节前，如果上一个字节没有被及时读走，就会被覆盖，造成数据丢失。

  • DMA（直接内存访问） 可以在不需要CPU干预的情况下，自动将接收到的字节依次存入你指定的数组缓冲区。即使CPU正在忙（比如处理其他中断、执行复杂计算），DMA也能在后台稳稳地把数据收完，只在接收完一组数据（例如一帧数据完成或半满）后才通知CPU来处理。
  • 这就相当于：CPU不参与每个字节的搬运，只负责整体处理，完全消除了“来不及读”的瓶颈。

DMA 是一个专门负责在内存和外设之间、或内存与内存之间搬运数据的“硬件小助手”。它可以在不需要CPU参与的情况下，独立完成大量数据的快速转移。

配置要素

  • 源地址：数据从哪里来。例如：&ADC1->DR（ADC数据寄存器的地址）。
  • 目标地址：数据要搬到哪里去。例如：&myBuffer[0]（你自己定义的数组的首地址）。
  • 传输数量：总共要搬多少个数据。例如：1000。
  • 传输方向：
    • 外设 → 内存（最常见，如ADC采集、接收UART数据）
    • 内存 → 外设（如发送UART数据、DAC输出波形）
    • 内存 → 内存（仅部分DMA支持，如M2M模式）
  • 触发源：什么时候开始搬一次数据。例如：
    • ADC转换完成信号
    • 定时器更新信号
    • UART接收寄存器非空信号
    • 软件触发
  • 循环模式：
    • 普通模式：搬完指定数量的数据后就停止。
    • 循环模式：搬完最后一个数据后，自动重新从头开始，无限循环（非常适合ADC连续采样、PWM控制）。

DMA 中断不是默认开启的。要产生“传输完成中断”，需要 显式使能中断使能位。

以标准库 / HAL 库为例：

  • 在 HAL 库中：__HAL_DMA_ENABLE_IT(hdma, DMA_IT_TC) 或在初始化结构体中设置 hdma.Init.PeriphDataAlignment 等参数后调用 HAL_DMA_Start_IT() 而非 HAL_DMA_Start()。
  • 在寄存器层面：需要设置 DMA_CCR 寄存器中的 TCIE (Transfer Complete Interrupt Enable) 位。

如果只配置了通道、地址、长度，并启动了 DMA，但 没有使能 TC 中断，那么传输完成后只会置起标志位（TCIF），但不会触发中断请求（NVIC 不会收到信号），自然无法执行中断服务函数。

工作流程

阶段1：触发与仲裁（对应通用流程的“DMA请求”）

  1. 事件触发：外设（如ADC、USART、定时器）发生一个事件，向外发送一个DMA请求信号。
  2. 请求映射：不同外设的请求通过“逻辑或”进入DMA控制器。关键：某时刻一个通道只能处理一个请求，所以需要在配置时选择正确的映射（如表8-xx）。
  3. 仲裁（优先级判断）：DMA控制器收到多个通道的请求后，根据以下规则决定先响应哪个：
    • 软件优先级（4级）：最高 > 高 > 中等 > 低（可编程）。
    • 硬件优先级（同软件级时）：通道编号越低，优先级越高（如通道2 > 通道4）。

阶段2：握手与总线控制（对应通用流程的“DMA响应”）

  • DMA控制器选择了高优先级的请求后，向外设发送一个应答信号（握手）。
  • 外设收到应答信号后，立即撤销请求。
  • DMA控制器检测到请求撤销后，也撤销应答信号。一次握手完成。
  • 注意：这里隐含了DMA控制器会通过总线裁决逻辑向CPU请求总线控制权的过程（与上一轮对话一致）。获得总线后，才进入下一阶段。

阶段3：传输控制（对应通用流程的“DMA传输”）

这是STM32 DMA的特色，你的资料详细描述了传输过程中的关键控制：

  • 数据宽度与地址自增：
    • 数据宽度可设（1、2、4字节）。
    • 外设和存储器的地址指针可独立选择是否自增（增量值 = 数据宽度）。
    • 常见场景：从ADC数据寄存器（固定地址）读取到数组（自增地址）。
  • 传输数量：可设置最大65535次传输。
  • 传输模式：
    • 非循环模式：传输完成（计数器归零）后停止DMA操作。
    • 循环模式：传输完成（计数器归零）后自动恢复初始值，并继续DMA操作。常用于ADC扫描模式、音频环形缓冲区。
  • 存储器到存储器模式：
    • 无需外设请求，直接触发DMA传输。
    • 注意：该模式不能与循环模式同时使用。通常用于大块内存复制。

阶段4：中断与结束（对应通用流程的“DMA结束”）

  • 中断类型（可独立使能）：
    • 半传输中断（HTIF）：当传输完成一半时置位，可产生中断。常用于双缓冲处理（在处理前半部分的同时，DMA继续填充后半部分）。
    • 传输完成中断（TCIF）：当传输计数器归零时置位，可产生中断。通知CPU数据已全部搬运完毕。
    • 传输错误中断（FEIF）：当DMA读写过程中发生总线错误时置位，可产生中断。此时硬件会自动清除该通道的配置寄存器位，并停止该通道操作。
  • 结束后的动作：
    • 非循环模式：通道停止，等待重新配置启动。
    • 循环模式：自动重置计数器，继续传输，直到被软件关闭。

ADC 是一个将连续的模拟电压信号（如 0V ~ 3.3V）转换为离散的数字值（如 0 ~ 4095）的硬件模块。

输入/输出通道是计算机与工业生产过程交换信息的桥梁。按照信号输入/输出的方式可 分为输入通道和输出通道。

单片机应用系统中的输入通道用于采集控制或测量对象的各类变量，其中数字信号可直接通过GPIO口输入，若信号幅值过小则需先经放大器放大以满足TTL或CMOS电平要求；

而连续变化的模拟信号必须先经模/数转换器（ADC）转换为数字量后才能被单片机处理，若原始物理量（如温度、压力、流量、速度等）是非电信号，则还需先通过传感器转换为模拟电信号，必要时再经放大器放大。

输出通道则承担数/模转换、功率放大驱动和干扰信号防治三项主要作用：

  1. 首先，单片机输出的数字控制信号需要通过D/A转换器（DAC）转换为模拟电压或电流；
  2. 其次，由于转换后的模拟信号通常功率不足，需要经过功率放大才能驱动外部负载；
  3. 最后，后向输出通道靠近控制对象，工作环境恶劣，驱动系统极易通过信号通道、电源、空间电磁场甚至机械方式对单片机系统造成干扰，因此必须采取信号隔离、电源隔离以及大功率开关过零切换等措施进行防治。

最终，单片机系统的处理结果可以以开关量、数字量或频率量的形式输出。

深入理解ADC模数转换器：原理、应用与STM32实战

ADC（模数转换器，Analog-to-Digital Converter） 是一种将连续的模拟电压信号转换为离散的数字量的电路模块，广泛用于嵌入式系统中采集传感器信号（如温度、光强、电压等）。

在 STM32 微控制器中，ADC 通常为 12 位逐次逼近型（SAR），支持单次、连续、扫描、间断等多种转换模式，并可使用软件或定时器、外部中断等触发采样。其关键参数包括分辨率（决定转换精度）、采样时间（影响转换速度和抗混叠能力）、参考电压 Vref（决定输入范围）以及通道数（可复用多个输入引脚）。

使用 ADC 时需注意：输入电压不得超过参考电压范围，避免浮空引脚造成读数抖动；合理选择采样时间和时钟频率；在噪声敏感场合可能需要硬件滤波或多采样平均；注意引脚映射与复用冲突。典型应用包括电池电压监测、麦克风信号采集、电位器读数和各类工业传感器接口。调试时，若 ADC 读数与预期偏差大，应依次检查参考电压、通道配置、采样时间、对齐方式（左对齐/右对齐）、是否启用 DMA 以及数据对齐后的数值转换公式是否正确。

模式控制

ADC的运行模式主要分为转换模式和组类型。

  • 转换模式：决定ADC“什么时候开始、什么时候结束”（比如单次、连续、扫描、间断）
  • 组类型：决定ADC“采集哪些通道、优先级如何”（规则组、注入组）

转换模式

  • **单次转换 (Single)**：触发一次，只转换所选“通道组”里的一个通道，然后停止。适合偶尔测量。
  • **连续转换 (Continuous)**：触发一次后，不停地将同一个通道的转换结果刷进寄存器。适合监测单一模拟量。
  • 扫描模式 (Scan)：触发一次，自动对“规则组”里所有选中的通道，从低到高依次转换一遍。必须配合DMA，否则ADC_DR里只能保留最后一个通道的值。
  • **间断模式 (Discontinuous)**：一种特殊的扫描。触发一次，只转换“规则组”里的一个（或几个）通道，再次触发才转换下一个。适合需要程序精确控制每个通道采样时机的场景。

组类型

  • 规则组：按部就班的日常工作。事先排好一个任务列表（比如先测温度、再测湿度、再测压力），ADC就按这个顺序一遍遍地循环执行。
  • 注入组：突发的紧急任务。不管当前规则组执行到哪一步，都要立刻打断，优先执行注入组的测量，测完再回去继续刚才被打断的规则任务。

中断和DMA请求

如果说规则组/注入组决定了“测什么、谁优先”，转换模式决定了“何时测”，那么中断和DMA就决定了“怎么把数据取走”以及“怎么通知CPU来处理”。

这两个是ADC数据搬运和事件通知的核心机制

  1. ADC 中断 规则组和注入组转换结束时能产生中断,当模拟看门狗状态位被设置为1时,也能产生 中断。它们都有独立的中断使能位。
  2. DMA 请求 因为规则通道转换的值存储在一个仅有的数据寄存器中,所以当转换多个规则通道时需 要使用 DMA,这可以避免丢失已经存储在 ADC_DR 寄存器中的数据。只有在规则通道转换 结束时才产生 DMA 请求,并将转换的数据从 ADC_DR 寄存器传输到用户指定的目的地址。

ADC中断：事件驱动的三大来源

ADC能触发中断的场景，恰好对应了三种典型需求：

中断来源 触发时刻 典型用途
规则组转换结束 (EOC) 每一个规则通道转换完成时置位 单次或间断模式下，逐通道处理数据
注入组转换结束 (JEOC) 整个注入组的所有通道都转换完成时置位 紧急事件处理完毕，通知CPU立刻读取 JDR1~4
模拟看门狗 (AWD) 被监控通道的电压超出设定阈值时置位 过压/欠压报警，无需CPU持续轮询比较

这三个中断各有独立的中断使能位（在 ADC_CR1 寄存器中），可以单独开启或关闭。注：规则组还有“序列结束 (EOS)”中断，在扫描模式下一个完整序列完成时触发，适合需要“一轮数据全取完再处理”的场景。使用建议：注入组的中断通常优先级设得比规则组更高，确保紧急数据被最先响应。

DMA请求：规则组多通道扫描的“必选项”

为什么规则组多通道必须用DMA？

规则组有16个通道，但只配了1个数据寄存器 ADC_DR。在扫描模式下，ADC会依次转换所有选中的规则通道。每转完一个，新结果就直接覆盖前一个。如果没有DMA，等CPU进中断来读时，ADC_DR里就只剩最后一个通道的值了，前面全丢。

DMA的工作时序：

ADC每完成一个规则通道的转换，就产生一个DMA请求。DMA控制器收到请求，立刻把 ADC_DR 中的数据搬运到用户指定的内存数组（uint16_t adc_values[16]）。全程无需CPU干预。等一轮扫描结束（EOS中断），内存数组里已经是整整齐齐的一整套通道数据了。

为什么注入组不需要DMA？

注入组只有4个通道，且每个通道都配有独立的 ADC_JDR1~JDR4 寄存器。转换结果各自安好、互不覆盖，CPU在注入转换结束中断里一次性全部读取即可。

串行通信协议

串行通信协议是指规定数据在单条信号线或差分信号线上按比特顺序逐个传输时所遵循的一组规则与标准，它涵盖了物理层（如电压电平、连接器引脚定义、传输速率）与数据链路层（如起始位、数据位、奇偶校验位、停止位、帧格式、流量控制、错误检测等）的具体约定，使得发送端与接收端能够同步并正确解析二进制数据流；

常见的串行协议包括UART（通用异步收发传输器）、I²C、SPI、RS-232、RS-485、CAN、USB、PCIe、以太网（虽常被视为并行或复杂串行，但底层仍依赖串行编码）等，它们因距离、速度、拓扑结构、成本和应用场景（如嵌入式设备内部通信、工业现场总线、汽车网络、外设连接、远距离传输）的不同而被选择。

简单来说，串行通信协议就像是两个人用一条电话线一个字一个字地对话，事先约定好语速、发音方式、单词长度、停顿间隔以及如何纠错，从而确保信息准确传达。

要建立稳定的串口通信，必须先统一双方的“语言规则”，即以下 5 个核心参数：

  • 波特率（Baud Rate）：单位时间内传输的二进制位数，常见值为 9600、115200、38400。例如 9600bps 表示每秒传输 9600 位（含起始位、数据位、校验位、停止位），实际有效数据率需剔除控制位。
  • 数据位（Data Bits）：每帧数据中包含的有效数据位数，通常为 8 位（对应一个字节），也有 7 位（适配 ASCII 码）。
  • 停止位（Stop Bits）：每帧数据结束后的标识位，可设为 1 位、1.5 位或 2 位，用于接收方判断一帧数据是否结束。
  • 校验位（Parity Bit）：用于校验数据传输是否出错，分为奇校验（数据位 + 校验位中 1 的个数为奇数）、偶校验（1 的个数为偶数）、无校验（最常用，依赖上层协议容错）。
  • 流控（Flow Control）：可选参数，用于防止数据溢出（如 RTS/CTS 硬件流控、XON/XOFF 软件流控），多数简单场景（如传感器数据传输）无需启用。

关键原理：发送方按参数封装数据帧（起始位 + 数据位 + 校验位 + 停止位），接收方按相同参数解析帧结构，若参数不匹配，接收数据会出现乱码（如波特率不匹配时常见“####”或乱码字符）。

UART（通用异步收发）

UART（通用异步收发传输器）是一种最基础且广泛使用的串行通信协议，其核心特点在于“异步”与“全双工”：

它不需要在数据传输线之外单独提供时钟信号来同步收发双方，而是通过预先约定相同的波特率（如9600、115200bps）、数据格式（起始位、数据位、奇偶校验位、停止位的位数与规则）以及相同的物理层电压逻辑，使得接收端能够根据起始位的跳变沿来自动校准字符内部的位边界；

在空闲时，发送端保持高电平（逻辑1），当需要发送一个字节时，先拉低电平一个周期作为起始位，随后按最低有效位优先的顺序依次发送5至9位数据，接着可选一位奇偶校验位用于简单检错，最后发送1至2位高电平的停止位以分隔连续字符。

由于不共享时钟信号，UART对收发双方的时钟精度要求较高（通常允许±2-5%的波特率误差），但同时也省去了时钟线，仅需发送（TX）、接收（RX）和地线（GND）三根线即可实现点对点双向通信，因此具有结构简单、成本低廉、兼容性极佳（几乎所有微控制器、计算机、工业设备均支持）的优点，主要应用于调试信息输出、GPS模块通信、蓝牙/串口转USB模块、老旧设备与PC之间的短距离低速数据传输等场景。

UART使用异步模式工作，不需要时钟信号，其一般格式为：起始位+数据位+校验位+停止位。其中起始位1位，数据位5~8位，校验位0或1位，停止位1、1.5或2位。不过最常用的格式是1位起始位、8位数据位、没有奇偶校验、1位停止位，简记为8/N/1。

空闲时数据线上规定为逻辑1。

开始传输数据时先发送起始位，规定为逻辑0，接收端会检测这个下降沿，以便之后开始采样接收数据。

起始位之后是数据位，规定先发送最低位，即LSB First。因为UART没有时钟信号，故使用波特率来确定每一位的长度，不过为保证检测的准确性，实际采样频率会高于波特率，一般每一位会进行若干次采样，取中间的采样值作为这一位的结果。

奇偶校验位一般不使用。

停止位一般使用1位，规定为逻辑1，除了表示传输结束外，停止位还可以起到时钟同步的作用。

需要注意的是，这里的逻辑0并不一定是0V，这与使用的电平标准有关。对于TTL电平而言，逻辑0是0V，逻辑1是高电平（一般为3.3V或5V）；对于RS-232电平而言，逻辑0是3V15V，逻辑1是-3-15V。

SPI（串行外设接口）

SPI（Serial Peripheral Interface，串行外设接口）是一种高速、全双工、同步的串行通信协议，由摩托罗拉公司提出，主要应用于芯片内部的短距离、高吞吐量数据传输。

与UART的异步方式不同，SPI通过独立的时钟线（SCK）来同步主设备（Master）与从设备（Slave）之间的每一位传输，因此发送端无需预先约定严格的波特率，通信速率可以达到数十兆赫兹甚至更高。其接口通常使用四根信号线：SCK（串行时钟，由主设备产生）、MOSI（主设备输出/从设备输入，用于主设备向从设备发送数据）、MISO（主设备输入/从设备输出，用于从设备向主设备发送数据）以及CS/SS（片选信号，低电平有效，主设备通过拉低某个从设备的CS线来选中该从设备）。

(27) SPI: The serial peripheral interface - YouTube

由于MOSI和MISO两条数据线独立且同时工作，SPI能够在同一时钟周期内完成发送和接收，实现了真正的全双工通信。工作时，主设备首先拉低目标从设备的CS引脚以激活该从设备，然后在每个SCK时钟边沿（上升沿或下降沿，依极性配置而定）同时移出和移入一位数据，通常8位为一个字节。

SPI协议没有固定的数据帧格式（如起始位、停止位），也不包含应答机制或流控制，因此单纯依靠硬件引脚的片选信号来选择从设备，整个通信完全由主设备控制。这种精简设计带来了极高的协议效率，但也导致了以下特点与局限：

  • 每个从设备需要独立的CS引脚，因此连接多个从设备时会占用较多主设备的GPIO（通用输入输出）资源；
  • 缺少应答和校验机制，发送端无法直接确认接收端是否正确收到数据，需要上层协议补充；
  • 没有定义多主设备冲突处理规则；传输距离极短（通常仅在电路板内部使用，线长不超过几十厘米）。

SPI因其高速度（常可达50MHz以上）和低协议开销，被大量用于对速度要求苛刻且通信距离极短的场景，例如：Flash存储器/EEPROM读写、SD卡（Secure Digital Memory Card，安全数字存储卡）通信、LCD/OLED显示屏驱动、模数转换器（ADC）/数模转换器（DAC）配置、实时时钟（RTC）、传感器（如加速度计、陀螺仪、温度传感器）数据采集，以及FPGA或数字信号处理器与外围芯片之间的高速数据交换。

模式 CPOL CPHA 空闲时钟 采样沿 典型器件

1 0 1 低 下降沿 部分ADC

SPI 的 CPOL（时钟极性）和 CPHA（时钟相位）决定了数据是在时钟的上升沿还是下降沿采样，以及空闲时钟电平是高还是低。如果主设备与从设备的 CPOL / CPHA 配置不一致，会导致采样点错位，最常见现象就是 读到的数据整体偏移一个字节（或几个位）。这种错位是 固定偏移，不会随机乱码，非常有规律。

I²C（双线串行总线）

I²C（Inter-Integrated Circuit，内部集成电路总线）是一种由飞利浦公司（现恩智浦半导体）于1982年发明的半双工、同步串行通信协议，它仅使用两条开漏（Open-Drain）信号线——串行数据线（SDA）和串行时钟线（SCL），配合上拉电阻即可实现多主设备（Multi-Master）与多从设备（Multi-Slave）之间的通信。

与SPI需要多个片选引脚不同，I²C通过唯一的7位或10位设备地址来寻址每个从设备，从而仅用两根线就能挂载多达上百个节点（受总线电容限制，标准模式下通常为数十个），极大地节省了微控制器的引脚资源。

  • 多主机，多从机（7位地址 = 最多 127 个设备）
  • 半双工
  • ACK/NACK 是协议核心，NACK 必须处理

在物理层，由于SDA和SCL均为开漏结构，任何设备都只能将线路拉低（输出逻辑0）或释放（高阻态），而高电平通过外部上拉电阻产生，这种设计允许多个设备无竞争地共享总线并实现仲裁机制。

“线与”：多个设备连接在同一根线上，只要 有一个 输出 0，那这根线就是 0；只有 所有 设备都输出 1（即释放总线），这根线才是 1。

  • 这很像“民主投票”：一票否决（0 是强势的），全票通过才是 1。

仲裁机制：

  • 如果主设备 A 想发送 1（释放总线），但主设备 B 想发送 0（拉低线路），那么线上的实际结果是 0。
  • I2C 协议规定，发送方要 回读 总线上的电平。当 A 发现自己想发 1 但总线是 0 时，就知道 有别人在抢总线，并且 A 会主动退出发送（失去仲裁）。
  • 这样，多个设备可以同时开始发送，不会烧坏引脚（因为开漏结构允许短接到地），并且 优先级高的设备（发 0 的）会赢，无损地完成传输。

在通信协议层面，I²C的帧结构具有明确的开始与停止条件：当SCL为高电平时，SDA发生下降沿表示起始信号（Start），上升沿表示停止信号（Stop）。所有数据传输以字节（8位）为单位，每个字节后跟随一个应答位（ACK，低电平有效），由接收端拉低SDA表示成功接收；若接收端不响应（保持高电平，即NACK），主设备可发出停止或重复起始信号。起始信号后，主设备先发送7位从设备地址和1位读写方向位（0表示写，1表示读），寻址到的从设备通过应答响应，随后按方向传输若干字节，每个字节后都有应答位，最终由停止信号结束总线会话。

I²C支持多种速率模式：标准模式（100 kbit/s）、快速模式（400 kbit/s）、快速模式+（1 Mbit/s）、高速模式（3.4 Mbit/s）以及超快速模式（5 Mbit/s，仅用于单向传输）。由于其地址空间有限，为应对地址冲突还扩展了10位寻址模式和软件协议（如D/C/I²C地址分配标准）。

I²C的主要优点包括引脚占用极少、支持多主设备仲裁（当多个主设备同时启动时，通过逐位比较SDA上的数据，丢失仲裁的一方主动退出）、内置应答检错机制、功耗较低，以及便于构建传感器网络。但它也存在明显局限：

  • 半双工通信意味着同一时刻只能单向传输，速度低于SPI；
  • 总线电容限制了传输距离（通常限于同一电路板或短电缆，约1-2米）；
  • 每个从设备需要唯一地址，且开漏结构的上拉电阻导致速率与功耗之间的权衡（上拉电阻越小速率越快但功耗越高）。

I²C广泛应用于各种低速外设的连接，例如温度传感器（如LM75）、加速度计、陀螺仪、磁力计、触摸屏控制器、EEPROM（24LC系列）、实时时钟（DS1307/DS3231）、模数转换器（如ADS1115）、I/O扩展器（PCF8574）、OLED/LCD显示模块（基于SSD1306等驱动），以及电源管理芯片与SoC之间的配置与控制。简而言之，I²C以两根线的极简成本，构成了嵌入式系统中设备间慢速控制与状态读取的骨干总线。

STM32 待机模式（Standby mode） 的一个重要特性：唤醒后相当于芯片复位。

首先要区分 STM32 的几种低功耗模式：

模式 唤醒后行为 内核状态 RAM 保持
睡眠模式 从断点继续执行 时钟停止，内核停止 全部保持
停机模式 从断点继续执行 时钟停止，内核停止 全部保持
待机模式 相当于硬件复位 完全掉电 丢失（除备份域）

关键点：

  • 待机模式（Standby） 唤醒后，芯片会执行 复位流程（从 Reset_Handler 开始，最终进入 main()）。
  • 题目说“唤醒后程序没有从 main 函数开始执行” —— 这句话本身可能意味着两种情况：
    1. 唤醒后压根没有执行代码（卡死/锁住）→ 可能是唤醒源配置错误，导致没有真正唤醒。
    2. 唤醒后执行了代码，但不是从 main() 开始（比如从复位中断向量开始）→ 这其实是正常现象，但题目的表述暗示“不符合预期”，所以可能用户预期是继续执行而不是复位。

结合常见考题，A 是出题人的预期答案：因为没有正确配置唤醒源，系统实际上是被 复位 了（而不是“唤醒后继续”），用户误以为没有从 main 开始执行。

HFSR（HardFault Status Register）和 CFSR（Configurable Fault Status Register）可以告诉你硬错误的具体原因（比如总线错误、用法错误、存储器管理等）。

STM32 的 RTC（Real-Time Clock）核心和它的寄存器位于 备份域（Backup Domain）。这个区域在以下情况下仍可保持供电：

  • 当主电源 VDD 断电时，如果 VBAT 引脚 连接了电池（如 CR2032），备份域会自动切换到 VBAT 供电。
  • 如果 VBAT 悬空或未接电池，主电源断电后，备份域也会掉电，RTC 的计数值和配置就会丢失（复位到默认值）。

因此，断电后时间丢失 最直接的原因是没有为 VBAT 提供后备电源，加电池就能解决。

  • STM32 进入 睡眠模式（Sleep） 时，CPU 时钟停止，但 GPIO 外设的电源和寄存器内容 不会掉电，GPIO 状态理论上应该保持不变。
  • 但在实际系统中，如果在睡眠期间发生了 意外复位（如看门狗、外部复位等），或者某些配置被意外修改，GPIO 状态可能改变。
  • GPIO 锁定机制（Lock Register） 可以防止 GPIO 配置（模式、输出类型、速度、上拉/下拉等）在锁定后被意外更改，直到下一次复位。
  • 对于需要 在睡眠模式下保持特定输出状态 的设计（如驱动功率管、保持继电器吸合等），在进入睡眠前 锁定 GPIO 配置 是一种可靠做法，可以避免被其他代码或事件误改。

注意：睡眠模式本身并不会重置 GPIO 输出。本题可能隐含了“防止外部干扰或代码误操作导致状态改变”的场景，因此锁定寄存器是最直接的方案。

  • 中断服务函数（ISR）应该 短小精悍，只做最紧急、最少的事情（如置标志位、清中断标志、保存数据），把耗时的处理放到主循环或任务中执行。
  • 如果 ISR 中做了太多事情（例如处理数据、调用复杂函数），当中断触发频率很高时，CPU 会频繁进入 ISR，导致主循环得不到执行机会。
  • 置标志位 的方式使得 ISR 只花几个 CPU 周期就退出，主循环可以正常轮询标志位并进行后续处理。

STM32 定时器的输入捕获单元使用 定时器时钟（通常是 APB 时钟，如 72MHz）对输入信号进行采样。由于输入信号相对于定时器时钟是 异步的，捕获操作存在一个固有的 ±1 个计数时钟周期 的量化误差。

这是 数字测量中的基本原理：使用一个频率为 ff 的时钟去测量一个异步事件的时间间隔，理论上误差范围是 ±1 个时钟周期。这个误差无法完全消除，只能通过提高定时器时钟频率来减小相对误差。

DAC 输出 = (DOR / 4096) × Vref+。如果 Vref+ 不准（如电压波动、未正确连接），输出偏差会成比例放大。这是首先要确认的。

SD 卡通过 SPI 通信时，使用 CS（片选）信号 来表示一次命令/数据传输的开始和结束。SD 卡协议规定：

  • CS 拉低：表示一次事务开始（命令或数据传输）。
  • CS 拉高：表示一次事务结束，SD 卡退出 SPI 模式的数据响应状态，回到命令等待状态。

常见错误：

  • 第一次操作后，忘记将 CS 拉高（仍保持低电平）。
  • 第二次操作前，没有重新拉低 CS（或者卡认为仍在之前的事务中，导致状态机混乱）。

这样会导致第二次操作时，SD 卡无法正确识别命令，从而返回错误或无响应。

SPI 擦除 Flash 芯片后数据未变化。原因是？

  • A. Flash 芯片写保护未解除 ✅
    很多 SPI Flash（如 W25Q64）有写保护引脚（WP#）或状态寄存器中的写保护位。如果未解除写保护，擦除/编程操作无效，数据保持不变。

STM32 启动模式由 BOOT0 和 BOOT1 引脚决定：

  • BOOT0 = 0 → 用户 Flash
  • BOOT0 = 1, BOOT1 = 0 → 系统存储器（ISP 模式）
  • BOOT0 = 1, BOOT1 = 1 → SRAM
    如果 BOOT0 被拉高且 BOOT1 = 0，就会进入系统存储器。这是最常见原因。

引脚输出期望 3.3V，但示波器显示高电平只有 2V。可能的原因是？

  • A. GPIO 输出驱动能力不足，负载过重 ✅
    STM32 GPIO 输出驱动能力有限（典型 20mA @ 3.3V）。如果负载电阻过小（如 100Ω），输出电压会被拉低。这是最常见原因。
  • B. 引脚配置为开漏输出且未接上拉 → 开漏输出且无上拉时，高电平由外部上拉电阻决定。若无上拉，引脚处于高阻态，示波器探头可能读到不确定电平（通常接近 0 或噪声，不一定是 2V）。
  • C. 芯片供电电压不足 → 如果 VDD 本身只有 2V，输出高电平不可能到 3.3V。但题中期望 3.3V，假设供电正常。
  • D. 示波器探头接地不良 → 接地不良可能导致测量值不准（偏高或偏低，不稳定），不太可能稳定显示 2V。
