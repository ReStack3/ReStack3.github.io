缓存友好

什么是缓存友好程序

在存储 - Hermes中我们谈到在计算机组成原理中的高速缓存。比如我们了解到现代CPU不是直接从内存读数据，而是分层：

  • L1 Cache（最快，最小）
  • L2 Cache
  • L3 Cache
  • 内存（最慢）

访问延迟大概是：

层级 延迟
L1 ~1ns
L2 ~3ns
L3 ~10ns
内存 ~100ns

如果一次缓存未命中（cache miss）≈ 性能下降一个数量级，所以在高性能系统开发里，“缓存友好（cache-friendly）”本质上是： 让程序尽可能利用CPU缓存，而不是频繁访问慢速内存（RAM）。或者说代码访问数据的方式，符合CPU缓存加载机制（空间局部性 + 时间局部性）：

  • CPU一次不是只加载一个变量，而是加载一整块（cache line，一般64字节）
  • 数据短时间内重复使用

举一个最经典的例子：

该代码的内存访问模式：a[0][0], a[1][0], a[2][0] ... → 地址不连续，频繁 cache miss。正确的写法是：

内存访问模式：a[0][0], a[0][1], a[0][2] ... → 预取有效，cache 命中率高。

如何做到缓存友好

数据布局优化

优先使用连续内存容器

用 vector / array 代替链表、哈希表、字典。尽量不使用链表遍历其每次跳跃都可能 cache miss，若需灵活性，考虑 gap buffer 或 Judy array（结合数组与链表的优点）

将一起访问的变量放在相邻位置

如果有几个变量被一起访问，它们应该被逐一声明。这就增加了另一个变量在处理器访问后已经在缓存中的可能性。因为在处理器访问了第一个变量之后，另一个变量已经在缓存中了。从而避免了缓存的缺失。

用值数组代替指针数组

vector<MyClass*> → 每次访问多一次间接寻址，破坏空间局部性。取而代之的使用 vector<MyClass> → 连续存储，缓存预取有效

对齐类/结构体到 cache line（通常 64 字节）

避免一个对象跨两个 cache line（否则访问一次需两次内存加载）

重排成员变量，消除编译器填充

可用 pahole 工具检测填充（Linux）

尽量使用最小够用的数据类型

能用 int 不用 long long，多个 bool 用位域或 char 数组。 注意：过小类型可能降低速度（处理器原生字长效率最高）→ 需实测

访问模式优化

矩阵遍历必须行优先（C/C++ 内存布局）

循环互换优化（以矩阵乘法为例）

仅此一项优化可提升 **76.6%**（Ulrich Drepper 实验）

合并同一数据的多次遍历

大数组时数据只加载一次到缓存

尽量减少写内存

写操作会使 cache line 变 “dirty”，最终需写回内存

  • 示例：选择排序中暂存最小值，最后只写一次

内存分配策略

尽可能使用栈分配

栈顶几乎总在缓存中，分配/释放极快，可变大小数组可用 变长数组（VLA）（GCC 支持）或 alloca()

避免频繁 malloc/free

批量分配一大块，自己管理（内存池），重复使用同一类型对象时，缓存释放的对象而不是真的 free

其他

正确对齐避免错位访问

软件预取（随机访问场景有效）

适用：二分查找、跳表、非线性访问

大工作集可提速 20%+，注意：小数据集或顺序访问反而是负优化

缓存友好链表（unrolled linked list）

每个节点存 多个值（如 4~8 个），遍历时间减少 **43%**，缓存缺失率从 10% 降至 3%
