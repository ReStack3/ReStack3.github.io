进程

什么是进程

进程（Process） 是操作系统进行资源分配和调度的基本单位，它是程序在计算机中的一次动态执行过程，包含程序代码、数据、内存空间、系统资源（如文件句柄、网络连接）以及执行状态等完整上下文环境。

当用户启动一个应用程序时，操作系统会为其创建一个独立的进程，该进程拥有虚拟的4GB地址空间（32位系统）、独立的堆栈、寄存器集合以及安全上下文，并与其他进程严格隔离——这意味着一个进程崩溃通常不会直接影响其他进程，这种隔离性通过内存管理单元（MMU）和操作系统的进程管理机制实现。

进程在执行过程中会经历创建（如Windows通过CreateProcess）、就绪、运行、阻塞和终止等多种状态变化，操作系统通过进程控制块（PCB）来记录每个进程的状态信息（如进程ID、优先级、资源占用等），并基于调度算法在多个进程间快速切换CPU时间片，从而形成多任务并发的效果。

现代操作系统还支持进程间通信（IPC）机制（如管道、共享内存、消息队列等）和子进程创建（如fork()），使得进程能够协作完成复杂任务，同时进程作为资源容器，其内部可以包含多个执行线程，这些线程共享进程的资源但能并行执行不同代码路径，从而进一步提高程序执行效率。

程序所需要的资源（数据、代码…）是由进程提供的；进程是一种空间上的概念，它的责任就是提供资源，至于资源如何使用，与它无关。

进程也可以理解为是一堆模块组成的，可以使用OD打开一个进程看一下：

这里面有很多的模块，每个模块都是一个可执行文件，它们遵守相同的格式，即PE结构，所以我们也可以理解进程就是一堆PE组合。

进程—空间提供资源(代码+数据)的,由多个模块(一个exe和多个dll—PE表)组成，提供代码和数据—遵循PE结构。

句柄

在 Windows 操作系统中，句柄（Handle） 是系统内核对象的核心引用机制，它本质上是一个不透明的数值标识符（通常为 32 位或 64 位无符号整数），由 Windows 内核动态生成并管理，用于唯一标识和访问系统资源（如文件、窗口、进程、线程、内存块、注册表键等）。

句柄表

概述

为了解决上述问题，在 Windows 操作系统中提供了句柄表。

句柄表是内核为每个进程维护的一个关键数据结构，它本质上是一个映射表，负责将用户态程序使用的句柄值（如 0x48、0x64 这类看似随机的数字）与内核态的实际对象（如文件、线程、窗口等内核结构体）建立安全关联。

微软设计句柄表的核心目的是实现用户态与内核态的严格隔离——当应用程序调用诸如 CreateFile 或 CreateThread 等 API 时，内核会在当前进程的句柄表中新增一条记录，分配一个唯一的句柄值并关联到新创建的内核对象（如 FILE_OBJECT 或 ETHREAD 结构体），但绝不会将内核对象的真实内存地址（如 0xFFFFF780A3B8C010）暴露给应用层。

这种设计从根本上杜绝了用户态程序直接操作内核内存的可能性：即使恶意程序获取了句柄值，也无法通过该值逆向推导出内核对象的内存布局或篡改其内部数据，因为所有通过句柄的操作都必须经过内核的合法性校验（例如检查进程是否具有对该句柄的读写权限）。

当应用程序调用 ReadFile 或 SetWindowText 等函数时，系统会通过当前进程的句柄表将用户传递的句柄值转换为实际的内核对象指针，并在执行操作前验证权限和有效性，若检测到非法访问（如尝试用文件句柄操作线程），则会立即返回 ERROR_INVALID_HANDLE 错误。

这种间接访问机制如同给内核对象加了一层保险箱，应用程序只能通过系统预定义的“钥匙”（句柄）按规则使用功能，而无法直接触碰保险箱内的物品（内核数据结构），从而确保了系统的稳定性和安全性。

想象你去游乐园，把背包存进储物柜：

  1. 储物柜（资源）：比如3号柜子，它实际存放你的背包（相当于系统资源，如窗口、文件）。
  2. 小票（句柄）：管理员给你一张小票，上面写“A12”（不是柜子本身，而是一个编号）–这个编号每次去都是随机的。你凭这个小票才能开柜取包。
    • 句柄就像小票：它本身不是储物柜（资源），但通过它你能操作储物柜。
    • 系统保护：没有小票的人无法乱开柜子（防止程序随意访问其他资源）。

句柄本质上就一个防火墙，将应用层、内核层隔离开来，通过句柄就可以控制进程内核结构体，我们得到所谓句柄的值实际上就是句柄表里的一个索引。

线程

什么是线程

线程（Thread）是操作系统能够进行运算调度的最小执行单元，它被包含在进程之中，是进程中的实际运作单位。

一个进程可以包含多个线程，所有线程共享进程的资源（如内存空间、文件句柄等），但每个线程拥有独立的程序计数器、寄存器集合和栈空间，使得它们能够并发执行不同的代码路径。

当操作系统调度程序分配CPU时间片时，是以线程为单位进行调度的，而非进程——即使属于同一个进程的多个线程也可能被分配到不同的CPU核心上并行运行（在多核系统中），这种特性使得线程成为实现并发编程的高效手段。

线程的创建、切换和销毁比进程更轻量级，因为不需要像进程那样涉及内存空间、文件描述符表等资源的重新分配，只需维护线程私有的执行上下文即可，但这也带来了线程同步的挑战（如竞态条件、死锁等问题），需要通过互斥锁、信号量等机制来协调对共享资源的访问。

现代操作系统通常提供用户态线程（由运行时库管理）和内核态线程（由操作系统直接管理）两种实现方式，前者切换开销小但无法利用多核，后者能真正并行但切换成本较高，某些系统（如Windows）采用一对一模型（每个用户线程对应一个内核线程），而Linux则通过更灵活的线程组（Thread Group）机制来平衡效率与功能。无论是哪种实现，线程的核心价值都在于通过共享地址空间内的多任务执行来提高程序的响应性和资源利用率。

线程安全问题

线程安全问题是指在多线程并发执行的环境下，当多个线程同时访问共享资源（如全局变量、内存数据、文件或硬件设备等）时，由于线程执行的随机性和不确定性，可能导致程序出现不可预期的错误行为，例如数据竞争（Data Race）、脏读（Dirty Read）、死锁（Deadlock）或计算结果不一致等问题。

这种问题的本质在于线程执行的交错性——由于操作系统对线程的调度是抢占式的，线程在执行过程中可能随时被中断，而其他线程对共享资源的修改可能破坏当前线程的执行逻辑。例如，若两个线程同时对一个全局计数器进行自增操作，由于“读取-修改-写入”这一系列操作并非原子性（Atomic）的，最终可能导致计数结果错误。类似地，当一个线程正在修改某个数据结构（如链表）时，若另一线程尝试读取或修改该结构，可能引发内存访问异常或逻辑错误。

为了解决这些问题，必须引入线程同步机制，通过对共享资源的访问施加约束，确保任一时刻只有一个线程能执行临界区（Critical Section）代码，或者通过协调线程间的执行顺序，实现数据的安全访问和操作的原子性。

常见的同步机制包括互斥锁（Mutex）、信号量（Semaphore）、条件变量（Condition Variable）、读写锁（Read-Write Lock）以及原子操作（Atomic Operations）等，它们从不同维度提供了线程间协同工作的基础能力，从而保障多线程程序的正确性和可靠性。

虚拟内存与物理内存的关系

虚拟内存与物理内存是现代计算机系统中两种密切相关但又各具特点的内存管理机制，它们共同构成了计算机的内存体系。物理内存是计算机硬件实际存在的内存芯片（如DRAM），其容量固定且直接由CPU通过内存总线访问，具有高速读写特性但价格较高；而虚拟内存是操作系统通过软硬件结合（MMU内存管理单元）为每个进程模拟出的连续、独立的地址空间，它通过分页或分段机制将虚拟地址映射到物理地址，使得每个进程都拥有看似独占的完整地址范围（如32位系统的4GB空间）。

当进程访问虚拟内存时，操作系统会检查页表完成地址转换：若目标页已在物理内存中（页命中），则直接访问；若不在（页缺失），则触发缺页中断，由操作系统从磁盘交换文件（pagefile.sys或swap分区）中调入所需页面到物理内存，必要时按特定算法（如LRU）换出其他页面以腾出空间。这种机制不仅扩展了可用内存容量（使小物理内存能支撑更大程序运行），还实现了进程间内存隔离（保障安全性）、内存碎片整理（虚拟地址连续而物理地址可分散）以及写时复制（Copy-on-Write）等优化技术。

值得注意的是，频繁的页面交换（抖动）会导致性能下降，因此实际有效内存容量仍受物理内存大小制约，虚拟内存本质是通过磁盘空间扩展内存容量的”以时间换空间”策略。

虚拟内存

虚拟内存是操作系统提供的一种内存管理技术，它为每个程序提供一个独立的、连续的虚拟地址空间，使得程序可以认为自己独占了整个内存资源，而实际上这些虚拟地址会被动态映射到物理内存或磁盘交换空间上。

核心特点：

  1. 扩展可用内存：即使物理内存不足，程序仍可运行，部分数据会被临时存储在磁盘（交换文件/swap分区）上。
  2. 内存隔离：每个进程拥有独立的虚拟地址空间，防止程序互相干扰，提高安全性。
  3. 地址转换：CPU通过MMU（内存管理单元）和页表将虚拟地址映射到物理地址。
  4. 按需加载：数据并非全部装入物理内存，而是按需调入（缺页中断触发加载）。
  5. 内存优化：支持分页、分段、写时复制（Copy-on-Write）等技术，提高内存利用率。

工作流程：

程序访问虚拟内存地址 → MMU查询页表 →

  • 命中：直接访问物理内存。
  • 未命中（缺页）：从磁盘加载数据到物理内存，必要时换出旧数据。

窗口的本质

在Win32体系下，窗口的本质是一个由操作系统内核管理的具有层次关系的消息处理单元，其核心是通过句柄（HWND）标识的GUI对象，具体表现为：

  1. 内核对象实体：每个窗口对应一个由Windows内核维护的数据结构（WND结构），存储位置、样式、状态等属性，并通过消息队列（Message Queue）接收系统或应用程序产生的输入/命令消息；
  2. 消息驱动机制：窗口的生命周期完全由消息循环（Message Loop）驱动，包括创建（WM_CREATE）、绘制（WM_PAINT）、销毁（WM_DESTROY）等所有行为都通过消息触发，形成”事件-消息-处理”的异步响应模型；
  3. 可视化与交互载体：窗口作为GDI/GDI+的绘制表面，管理着客户区/非客户区的图形渲染，同时通过消息映射将用户输入（鼠标/键盘事件）转化为可编程事件（如WM_LBUTTONDOWN）；
  4. 资源管理单元：窗口句柄关联着所属线程的消息队列、设备上下文（DC）、子窗口链表等资源，其销毁会级联释放相关GDI对象，体现为线程绑定的资源容器。

GDI - 图形设备接口

GDI（Graphics Device Interface）是Windows操作系统最核心的图形子系统，它作为应用程序与图形硬件之间的抽象层，提供了设备无关的二维图形绘制能力。

关键组件

  • 设备上下文（DC）：绘图操作的画布对象
  • GDI对象：画笔、画刷、字体等绘图工具
  • 坐标系统：逻辑单位到设备像素的映射
  • 绘图模式：ROP2（光栅操作）代码控制绘制效果

消息

在Win32编程中，消息（Message）是Windows操作系统的核心通信机制，本质上是系统与应用程序之间、应用程序内部各窗口之间传递事件和指令的数据包。

当用户操作（如点击鼠标、按下键盘）、系统事件（如窗口大小调整）或应用程序内部请求发生时，Windows会将这些动作封装为包含特定信息的MSG结构体，通过消息队列传递给目标窗口。每个消息由三要素构成：消息类型（如WM_PAINT表示绘制请求）、附加参数（wParam和lParam，承载具体信息如坐标值或控件ID）以及目标窗口句柄。

应用程序通过消息循环（GetMessage/DispatchMessage）不断从队列中提取消息，并由窗口过程函数（WndProc）解析处理，形成”事件-消息-响应”的驱动模式。这种机制实现了异步事件处理、多窗口协作和用户输入响应，是Windows图形界面程序的基础架构，其特点包括：严格的类型分类（系统/控件/自定义消息）、优先级投递规则（SendMessage立即执行，PostMessage排队处理）以及线程关联性（每个GUI线程拥有独立消息队列）。

消息队列

消息队列是Windows GUI应用程序运行的核心机制，它构成了Windows事件驱动编程模型的基础。在Win32窗口编程中，消息队列负责管理系统和应用程序之间的通信。

基本概念

Windows操作系统为每个GUI线程维护一个消息队列，这个队列存储着各种输入消息（如键盘、鼠标输入）、系统消息（如窗口管理）和应用程序自定义消息。当用户与窗口交互或系统事件发生时，Windows会将这些事件转换为消息并放入相应线程的消息队列中。

消息队列的类型

系统消息队列：由操作系统维护的全局队列，接收原始硬件输入事件（如键盘敲击、鼠标移动）

线程消息队列：每个GUI线程有自己的消息队列，接收已分派到特定线程的窗口消息，包括输入消息、WM_系列窗口消息等

消息处理流程

消息产生：

  • 硬件事件（如鼠标点击）被转换为WM_消息
  • 系统事件（如定时器到期）产生WM_TIMER消息
  • 应用程序可以主动发送消息（PostMessage/SendMessage）

消息投递：

  • 系统将消息放入相应线程的消息队列
  • 对于PostMessage，消息被放入队列尾部
  • 对于SendMessage，直接调用窗口过程（不经过队列）

消息循环：

消息处理：DispatchMessage调用目标窗口的窗口过程(WndProc)，窗口过程处理消息或调用DefWindowProc进行默认处理

隐式链接

在编译阶段就告诉链接器需要用某个 DLL 对应的 **import library (.lib)**，运行时系统会自动加载 DLL。

  1. 编译时链接 .lib 文件 → EXE 中包含 DLL 的符号信息
  2. 程序启动时 → 系统自动寻找 DLL 并加载
  3. 调用 DLL 内函数像调用普通函数一样，无需 GetProcAddress

什么是注册表

Windows 注册表（Registry）是 Windows 操作系统的核心层次数据库，用于集中存储系统和应用程序的配置信息。它采用树形结构组织数据，由键（Key）、子键（Subkey）和值项（Value Entry）构成，类似文件系统的目录结构。

注册表包含五个主要根键，系统启动时，内核会加载注册表到内存中，所有应用程序通过 Win32 API（如 RegOpenKeyEx、RegSetValueEx 等函数）访问这些数据。注册表取代了早期 Windows 使用的 INI 文件，具有更高的安全性（支持 ACL 权限控制）、更强的数据类型支持（可存储二进制、字符串、DWORD 等多种数据格式）以及更高效的读写性能。它不仅维护着系统核心参数（如驱动程序配置、服务启动项），还管理着应用程序设置（如用户首选项、许可证信息），甚至控制着 Windows 用户界面行为（如桌面主题、菜单动画）。

由于注册表直接关联系统稳定性，不当修改可能导致系统故障，因此微软提供了注册表编辑器（regedit.exe）和命令行工具（reg.exe）进行可视化操作，同时强烈建议修改前备份注册表（通过导出 .reg 文件或使用系统还原点）。

注册表由以下主要根键组成：

  • HKEY_CLASSES_ROOT (HKCR): 文件关联和 COM 对象注册
  • HKEY_CURRENT_USER (HKCU): 当前用户配置
  • HKEY_LOCAL_MACHINE (HKLM): 系统全局配置
  • HKEY_USERS (HKU): 所有用户配置
  • HKEY_CURRENT_CONFIG (HKCC): 当前硬件配置

打开注册表键 - RegOpenKeyEx

Opens the specified registry key. Note that key names are not case sensitive.

To perform transacted registry operations on a key, call the RegOpenKeyTransacted function.

访问权限标志：

  • KEY_QUERY_VALUE: 查询键值
  • KEY_SET_VALUE: 设置键值
  • KEY_CREATE_SUB_KEY: 创建子键
  • KEY_READ: 组合读权限
  • KEY_WRITE: 组合写权限
  • KEY_ALL_ACCESS: 完全控制
